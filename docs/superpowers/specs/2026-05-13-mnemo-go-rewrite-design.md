# mnemo Go rewrite — design

**Date:** 2026-05-13
**Branch:** `feat/go-server-rewrite`
**Status:** Draft, pending implementation plan

## Summary

Replace mnemo's AWS-native stack (CDK + Lambda + AgentCore Memory + DynamoDB + S3 + SQS + SNS + EventBridge + SES) with a single self-hosted Go service backed by a dedicated Postgres container, deployed on the same VPS as auris. Same public REST API, 8 memory dimensions, same CLI and Chrome extension. Lower operational surface area, no AgentCore dependency.

## Goals

1. Drop-in replacement for the existing API: `POST /events` and `GET /recall` produce byte-compatible request/response shapes so the CLI and Chrome extension continue to work after a base-URL and credential swap.
2. Preserve 8 memory dimensions: `preferences`, `episodes`, `about`, `project`, `task`, `daily_log`, `daily_summary`, `meeting`. (The original spec listed `facts` as a 9th; it was removed mid-implementation since `about`/`project`/`task` subsume it.)
3. Run on the existing VPS via docker-compose, mirroring auris's deploy pattern (GHCR image, dedicated Postgres, Caddy + Cloudflare Origin Certificate).
4. Make `--attr` metadata first-class queryable on recall — a capability AgentCore could not provide.
5. Two-actor multi-tenancy from day one (user + spouse) via Auth0 sub-claim resolution.

## Non-goals (v1)

- Semantic recall (`?q=` is accepted but ignored; recency-ordered).
- Embeddings or pgvector.
- Migration of existing AgentCore data (fresh start).
- A Bedrock LLM implementation (interface exists; Anthropic is the only impl).
- Admin UI, metrics endpoint, rate limiting, multi-region.

## Architecture

A single Go binary, `mnemo-server`, runs as a long-lived service on the VPS behind Caddy. It serves the public REST API on one HTTP port and runs background goroutine workers in the same process. Persistent state lives in a dedicated Postgres container.

```
┌──────────────────────────────────────────────────────┐
│           VPS (same host as auris)                   │
│                                                      │
│  Caddy ──TLS──▶ mnemo-server  ───▶  Postgres         │
│                  │                  (dedicated       │
│                  ├── REST API        container)      │
│                  └── workers ┐                       │
│                              │                       │
│                              └─▶ Anthropic API (LLM) │
└──────────────────────────────────────────────────────┘
```

### Process layout

- `cmd/mnemo-server/main.go` — wiring, signal handling, graceful shutdown.
- `internal/api/` — HTTP handlers (`/events`, `/recall`, `/healthz`).
- `internal/auth/` — Auth0 JWT verification, JWKS cache.
- `internal/store/` — Postgres access; `database/sql` + `pgx/stdlib`, queries generated by `sqlc`.
- `internal/extract/` — context extractor (project/task/about/daily-log/preferences/episodes).
- `internal/meeting/` — meeting finalizer.
- `internal/digest/` — daily digest worker + in-process scheduler.
- `internal/llm/` — `Client` interface; `anthropic.go` implementation.
- `internal/queue/` — Postgres-backed job claim + retry/backoff.
- `internal/config/` — env loading.

### Concurrency model

The API goroutines write to Postgres and enqueue jobs in the same transaction. A worker pool (size from env, default 4) calls `SELECT ... FROM jobs ... FOR UPDATE SKIP LOCKED LIMIT 1` in a loop, processes a job, commits. SIGTERM stops accepting new HTTP requests, waits for in-flight workers up to a 30s drain timeout, then exits. Workers are idempotent on retry.

## Data model

One Postgres database (`mnemo`). Schema migrations live in `server/migrations/` and run on boot. All long text in `text`, structured data in `jsonb`, timestamps in `timestamptz` (UTC).

### `actors`

Replaces today's DynamoDB actors table.

| Column          | Type        | Notes                                  |
|-----------------|-------------|----------------------------------------|
| `actor_id`      | text PK     | Auth0 `sub` claim                      |
| `display_name`  | text        |                                        |
| `email`         | text        | Nullable; required for digest delivery |
| `timezone`      | text        | IANA, default `UTC`                    |
| `digest_enabled`| boolean     | Default `false`                        |
| `created_at`    | timestamptz | Default `now()`                        |

### `events`

Raw push from `/events`. The S3-replacement transcript log. Permanent — never deleted.

| Column          | Type        | Notes                                                              |
|-----------------|-------------|--------------------------------------------------------------------|
| `event_id`      | uuid PK     |                                                                    |
| `actor_id`      | text FK     |                                                                    |
| `session_id`    | text        |                                                                    |
| `project`       | text        | Nullable; null for global sessions                                 |
| `source`        | text        | e.g. `claude-code-hook`, `auris`                                   |
| `workstation`   | text        | Nullable                                                           |
| `workdir`       | text        | Nullable                                                           |
| `turns`         | jsonb       | `[{role, content, ...}]`                                           |
| `attributes`    | jsonb       | Default `'{}'`; arbitrary `--attr k=v`; queryable via GIN          |
| `meeting_id`    | text        | Denormalized from `attributes`; nullable                           |
| `meeting_ended` | boolean     | Denormalized from `attributes`; default `false`                    |
| `created_at`    | timestamptz | Default `now()`                                                    |

Indexes: `(actor_id, created_at desc)`, `(actor_id, meeting_id)` partial where `meeting_id is not null`, GIN on `attributes`.

### `memories`

Unified store for all 8 dimensions. One row per logical memory record.

| Column            | Type        | Notes                                                                 |
|-------------------|-------------|-----------------------------------------------------------------------|
| `memory_id`       | uuid PK     |                                                                       |
| `actor_id`        | text FK     |                                                                       |
| `dimension`       | text        | enum of the 8 dimension names                                         |
| `namespace`       | text        | e.g. `/projects/<actor>/<project>/`, `/meetings/<actor>/<id>/summary/`|
| `content`         | text        |                                                                       |
| `attributes`      | jsonb       | Default `'{}'`                                                        |
| `source_event_id` | uuid FK     | Nullable; null when consolidated from many events                     |
| `created_at`      | timestamptz | Default `now()`                                                       |
| `updated_at`      | timestamptz | Default `now()`                                                       |

Unique constraint on `(actor_id, namespace)` for consolidated dimensions (about, project, task, daily_summary, meeting). Append dimensions (daily_log, episodes, preferences) get fresh rows on each extraction. Note: each meeting produces 6 rows (one per category), all consolidated within their own namespace — a retry of `finalize_meeting` overwrites the same 6 rows.

Indexes: `(actor_id, dimension, created_at desc)`, `(actor_id, namespace)`, GIN on `attributes`, GIN on `to_tsvector('simple', content)` (free FTS support for future `?q=`).

### `jobs`

In-process worker queue.

| Column        | Type        | Notes                                                       |
|---------------|-------------|-------------------------------------------------------------|
| `job_id`      | bigserial PK|                                                             |
| `kind`        | text        | `extract_context` \| `finalize_meeting` \| `daily_digest`   |
| `payload`     | jsonb       |                                                             |
| `state`       | text        | `pending` \| `running` \| `failed` \| `done`                |
| `attempts`    | int         | Default `0`                                                 |
| `last_error`  | text        |                                                             |
| `run_after`   | timestamptz | Default `now()`; bumped on retry                            |
| `locked_by`   | text        | Worker id, nullable                                         |
| `locked_at`   | timestamptz |                                                             |
| `created_at`  | timestamptz |                                                             |

Workers claim with `UPDATE jobs SET state='running', locked_by=$1, locked_at=now() WHERE job_id = (SELECT job_id FROM jobs WHERE state='pending' AND run_after <= now() ORDER BY job_id FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING ...`. Backoff schedule: `30s, 2min, 10min`, then `failed`. `done` rows pruned after 7 days by a periodic in-process sweeper.

### No meeting staging

The old `meeting_staging` namespace existed to work around AgentCore's inability to query raw events back. In Postgres, `events` is durable and queryable, so the meeting finalizer reads directly:

```sql
SELECT event_id, turns, attributes, created_at
FROM events
WHERE actor_id = $1 AND meeting_id = $2
ORDER BY created_at;
```

Side benefit: raw events are never deleted, so a future "give me the verbatim transcript" recall mode is a schema-free addition.

## API

Two public endpoints + a health endpoint. JSON over HTTPS. All requests carry `Authorization: Bearer <jwt>` (Auth0 access token).

### `POST /events`

Request:

```json
{
  "session_id":  "claude-2026-05-13-...",
  "project":     "mnemo",
  "source":      "claude-code-hook",
  "workstation": "personal-laptop",
  "workdir":     "/Users/tiago/...",
  "turns": [
    {"role": "user",      "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "attributes": {
    "owner": "tiago",
    "priority": "high",
    "meeting_id": "design-2026-05-13",
    "meeting_ended": false
  }
}
```

Response: `202 Accepted` with `{"event_id": "<uuid>"}`.

Handler flow:

1. Validate JWT, resolve `actor_id` from `sub` claim (auto-insert into `actors` on first sight).
2. Insert into `events`.
3. Enqueue `extract_context` job.
4. If `attributes.meeting_ended == true`, also enqueue `finalize_meeting`.
5. Commit transaction. Return.

LLM never runs synchronously.

### `GET /recall`

```
GET /recall?preferences=1&about=1&project=mnemo
           &task=coding&date=2026-04-15&meeting=design-2026-05-13
           &q=anything-ignored-for-now
           &attr.owner=tiago&attr.priority=high
           &visible=true
```

Each enabled dimension is queried in its own goroutine against `memories` with the right `namespace` prefix, then merged. `attr.<key>=<value>` filters all dimensions on the `attributes` jsonb. `?q=` is accepted but ignored (recency-ordered response). `?visible=true` returns markdown render; `false` returns structured JSON.

Response shape is **byte-for-byte the same as today's API**.

### `GET /healthz`

`200 OK` with `{"ok": true, "db": true}` after `SELECT 1`. Wired into the docker-compose healthcheck.

### Auth flow

- `internal/auth/jwks.go` fetches and caches the Auth0 JWKS with TTL + background refresh. Verifies RS256 signature, `iss`, `aud`, `exp`, `nbf`.
- On success, extracts `sub`, resolves to an `actor_id`. First request from a new `sub` inserts a row in `actors` with `display_name = sub`, `digest_enabled = false`. User can later edit via SQL to add email and enable digests.
- CLI authenticates via OAuth Device Authorization Flow: `mnemo login` posts to Auth0's `/oauth/device/code`, prints the user code + verification URL, polls `/oauth/token`. On success, writes `{access_token, refresh_token, expires_at}` to `~/.mnemo/credentials` (mode 0600). Subsequent invocations transparently refresh.
- Chrome extension reuses the popup-OAuth pattern from auris.
- Auris's M2M integration: a long-lived Auth0 M2M client credential, stored in auris's `.env.deploy` as `AURIS_MNEMO_API_KEY` (variable name unchanged; semantics shift from API key to client credential).
- Dev escape hatch: `MNEMO_AUTH_DISABLED=1` bypasses JWT verification, maps every request to a synthetic `dev-actor`. Loud WARN log on boot.

### Errors

- `400` — malformed JSON, missing `session_id`, empty `turns`.
- `401` — missing/invalid JWT.
- `403` — valid JWT, sub has no actor row and auto-create is disabled (path exists for future "invite-only").
- `5xx` — Postgres failure. Container auto-restarts via compose `restart: unless-stopped`. Client retries.

## Extractors and workers

Three job kinds, each a port of an existing Lambda. LLM prompts move across mostly verbatim.

### `extract_context`

Triggered: every `/events` insert.
Payload: `{actor_id, event_id}`.
Ports: `infra/lambda/context-extractor/index.ts`.

Four parallel Claude calls via `errgroup`:

1. **Classify + extract project/task/daily-log facts.** Returns `task_domain ∈ {coding, studying, meeting, general}` plus optional project facts, task-domain facts, daily-log entries. Writes:
   - `project` dimension: upsert at `/projects/<actor>/<project>/` after a consolidation prompt.
   - `task` dimension: upsert at `/tasks/<actor>/<task_domain>/` after a consolidation prompt.
   - `daily_log` dimension: append at `/daily/<actor>/<YYYY-MM-DD>/log/`.
2. **Biographical (about).** Same prompt as today. Trust user turns, trust assistant turns only when grounded in user-supplied material, skip code/path/port details. Always runs the consolidation prompt to enforce narrative paragraph shape. Upsert at `/about/<actor>/`.
3. **Preferences.** Net-new prompt. Extract durable user preferences (coding style, tool choice, workflow). Append-only insert at `/preferences/<actor>/`.
4. **Episodes.** Net-new prompt. Extract structured episodes (event + reflection pairs). Append-only inserts at `/episodes/<actor>/`. (The `facts` dimension was dropped — biographical facts go to `about`, project facts to `project`, task-domain facts to `task`.)

Wall time ≈ slowest call (~2–5s with Sonnet). Latency irrelevant — background job.

Idempotency: consolidated-dim upserts are by-design idempotent. Append-dim writes use a delete-and-rewrite pattern on retry — the worker first deletes any prior append-dim rows for this `source_event_id` (in dimensions extracted by this job), then re-inserts the fresh extraction. Precise mechanism (delete-and-rewrite vs. a `(source_event_id, dimension, content_hash)` unique key) is settled in the implementation plan.

### `finalize_meeting`

Triggered: every `/events` insert with `attributes.meeting_ended == true`.
Payload: `{actor_id, meeting_id}`.
Ports: meeting finalizer block in `context-extractor/index.ts` (post-commit `b808b2b`).

```
events := SELECT * FROM events WHERE actor_id=$1 AND meeting_id=$2 ORDER BY created_at;
transcript := concatenate turns chronologically;
result := one Sonnet call -> JSON with {summary, decisions, actions, questions, highlights, followups};
for each category in [summary, decisions, actions, questions, highlights, followups]:
    INSERT INTO memories (...) VALUES (
        actor=..., dimension='meeting',
        namespace='/meetings/<actor>/<meeting_id>/<category>/',
        content=result[category], ...
    ) ON CONFLICT (actor_id, namespace) DO UPDATE SET content = EXCLUDED.content, updated_at = now();
```

Idempotent: re-running overwrites the same 6 rows with the same content.

### `daily_digest`

Triggered: in-process scheduler. A goroutine wakes once per minute, reads digest-enabled actors, and for each one whose local time matches their configured digest hour (computed via `actors.timezone`), checks `jobs` to avoid duplicate enqueues, then inserts a `daily_digest` job with `{actor_id, date}`.
Ports: `infra/lambda/daily-digest/index.ts`.

Worker steps:

1. Read `daily_log` rows for `(actor_id, date)` from `memories`.
2. One Sonnet call → structured summary (projects, decisions, learnings, time allocation, blockers, reflection).
3. Upsert into `daily_summary` dimension at `/daily/<actor>/<date>/summary/`.
4. If `actors.email` is set, send via SMTP.

Replaces today's EventBridge → dispatcher Lambda → SQS → digest Lambda chain.

### Email delivery

Three env vars: `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`. Disabled if unset (digest still stores the summary). `net/smtp` stdlib, ~80 lines.

### LLM client

```go
type Client interface {
    Complete(ctx context.Context, req CompleteRequest) (CompleteResponse, error)
}
```

`anthropic.go` is the only v1 implementation. POSTs to `https://api.anthropic.com/v1/messages` with `ANTHROPIC_API_KEY` and `MNEMO_LLM_MODEL` (default `claude-sonnet-4-7-20251015`). Interface exists so a future `bedrock.go` slots in without touching extractor code.

### Observability

- Structured `slog` JSON logs to stdout. Captured by Docker.
- `/healthz` for compose liveness.
- `jobs.state`, `jobs.attempts`, `jobs.last_error` are the debug surface. `SELECT * FROM jobs WHERE state='failed' ORDER BY job_id DESC LIMIT 20;` replaces the CloudWatch dashboard.
- No `/metrics` in v1.

## Testing

Standard `testing` package, three tiers:

- **Unit** (`*_test.go` next to each file): queue claim/retry, JWT verification (hand-minted RSA keys), extractors with a stub `llm.Client`, store helpers via `testcontainers-go` Postgres.
- **Integration** (`internal/integration/*_test.go`): full server binary + Postgres + stub LLM HTTP server. ~5–10 end-to-end flows per dimension. Run on every push via GitHub Actions.
- **Out of scope**: LLM output quality (validated in production), Chrome extension (manual smoke test), Caddy/TLS (standard).

The existing `infra/` directory (CDK) is deleted as part of the cutover.

### `docker-compose.deploy.yml`

Mirrors auris's pattern beat-for-beat:

- `postgres:16-alpine` with `pg_isready` healthcheck, named volume `mnemo-pg-data`.
- `mnemo-server` from `ghcr.io/tiagodeoliveira/mnemo-server:${SERVER_TAG:-latest}`, bound to `127.0.0.1:${SERVER_PORT:-8080}`, `depends_on: postgres` healthy.
- `caddy:2-alpine` reading `Caddyfile` with `{$DOMAIN}` / `{$PORT}`, Cloudflare Origin Certificate in `./certs/`.
- Env var groups: Required (`DATABASE_URL`, `AUTH0_DOMAIN`, `AUTH0_API_AUDIENCE`), LLM (`ANTHROPIC_API_KEY`, `MNEMO_LLM_MODEL`), SMTP (`SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`), Toggles (`MNEMO_AUTH_DISABLED`, `MNEMO_LLM_DISABLED`).
- No `expose` ports leak; everything goes through Caddy.
- `.env.deploy.example` documents every variable with comments, same shape as auris's.

### CI

Two GitHub Actions workflows:

- `test.yml` — `go test ./...` with testcontainers on every PR.
- `release.yml` — on push to `main`, builds the docker image, pushes to `ghcr.io/tiagodeoliveira/mnemo-server` tagged `latest`, `sha-<short>`, and git tag if present.

## Cutover

Fresh-start migration:

1. Stand up new server in production with Auth0 tenant + audience (one tenant shared with auris).
2. `mnemo login` from each laptop (device flow) → token in `~/.mnemo/credentials`. Two actors.
3. Edit `~/.mnemo/config.json` to point at the new base URL. Remove old `apiKey`.
4. Smoke test: push an event, recall it, push a meeting-end, verify the six category rows.
5. Update Chrome extension's stored config (existing options page) to new URL + Auth0.
6. Update auris's `.env.deploy`: point `AURIS_MNEMO_URL` at new server, swap `AURIS_MNEMO_API_KEY` for the Auth0 M2M credential.
7. Run both stacks side-by-side for a week. New mnemo is source of truth from day one.
8. `cdk destroy` old stack. Delete `infra/` from repo.

## Things that come free with the rewrite

- Queryable `--attr` metadata via `attr.<key>=<value>` recall filters.
- `updated_at` on consolidated memories visible in queries — easy to spot stale rows.
- Idempotent meeting finalizer (re-runnable without state cleanup).
- Raw events queryable forever, opening the door to a future "show me what I said in this meeting verbatim" recall mode.
- `slog` JSON logs locally inspectable with `docker compose logs -f`.

## Open questions

None at this point — everything below the API contract is implementation detail to be settled in the plan.
